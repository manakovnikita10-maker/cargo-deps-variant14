# Вторая практическая работа. Вариант 14

Инструмент для анализа графа зависимостей пакетов Cargo. Программа читает индекс Cargo
или тестовый JSON, строит граф рекурсивным поиском в глубину (DFS)
и выводит список смежности.

## Запуск

Требуется Python 3.10 или новее. На macOS и Linux используйте `./run.sh`.
На Windows используйте `py -3 -m src.main` с теми же опциями. Установка
Python-библиотек и сборка не нужны.

| Параметр | Назначение |
| --- | --- |
| `--package` | Имя пакета. В тестовом режиме используется буква A–Z. |
| `--version` | Полная версия пакета Cargo. Обязательна в сетевом режиме. |
| `--repository` | URL индекса Cargo или путь к локальному JSON. По умолчанию используется индекс crates.io. |
| `--test` | Читать тестовый репозиторий из файла. |
| `--filter` | Подстрока имени для исключения пакетов. |

```sh
./run.sh --package quote --version 1.0.40 --filter ident
python3 -m unittest discover -s tests -v
```

Команды с ошибочными значениями возвращают код 2 и сообщение о параметре.
Примеры для защиты этапа:

```sh
./run.sh --package ../quote --version 1.0.40
./run.sh --package quote --version 1.0
./run.sh --package quote --version 1.0.40 --repository invalid
./run.sh --test --package A
./run.sh --package quote --version 1.0.40 --filter " "
```

## Данные из Cargo

Официальный sparse-индекс хранит отдельный файл для каждого пакета.
Каждая строка файла содержит JSON с версией, зависимостями и служебными
полями. Например, файл пакета `quote` имеет путь `qu/ot/quote`.
Узлы Cargo помечены как `имя@версия`. Для каждого ребра выбирается
максимальная неотозванная версия, подходящая под ограничение SemVer.
В граф входят обычные, сборочные, опциональные и платформенные
зависимости, объявленные в текущем индексе. Зависимости разработки
пропускаются. Выбор Cargo по features, платформе и Cargo.lock может
давать другой результат.

```sh
./run.sh --package quote --version 1.0.40 --repository https://index.crates.io/
./run.sh --package quote --version 999.0.0
```

[Формат индекса Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html)

## Тестовый граф

Файл `tests/graph.json` задаёт список зависимостей для каждой вершины.
В примере есть цикл B → D → B, общая зависимость D и отдельная вершина F.

```sh
./run.sh --test --repository tests/graph.json --package A
./run.sh --test --repository tests/graph.json --package A --filter C
./run.sh --test --repository tests/graph.json --package F
```

DFS помечает вершину до рекурсивного обхода соседей. Поэтому ребро цикла
попадает в результат, а повторный обход вершины прекращается. Фильтр
учитывает имя без версии и регистр букв игнорируется. Начальная вершина
сохраняется, отфильтрованные зависимости не обходятся.

## Обратные зависимости

Режим `--reverse` разворачивает рёбра и выполняет тот же рекурсивный DFS.
В выводе находятся пакеты, которые зависят от выбранного пакета напрямую
или через другие пакеты. Начальная вершина исключается из списка даже
при наличии цикла.

```sh
./run.sh --test --repository tests/graph.json --package D --reverse
./run.sh --test --repository tests/graph.json --package D --reverse --filter C
./run.sh --test --repository tests/graph.json --package G --reverse
```

Для D выводится последовательность B, A, C, G. С фильтром C остаются
B и A. Для G список пуст. Поиск в JSON охватывает весь файл.

В режиме Cargo укажите `--within ИМЯ@ВЕРСИЯ`. Sparse-индекс позволяет
получить данные по имени пакета, поэтому поиск ограничен графом
зависимостей указанного корня.

```sh
./run.sh --package serde_core --version 1.0.228 --reverse --within serde@1.0.228
```
