# Конфигурационное управление · Практика №2 · Вариант 14

Консольная программа строит граф зависимостей опубликованного пакета
Rust/Cargo или локального тестового репозитория. Граф сохраняется в
форматах Graphviz DOT и SVG. SVG открывается в браузере.

## Запуск и тесты

Требуется Python 3.10 или новее. Graphviz должен быть установлен, а
команда `dot` доступна в `PATH`. Сборка и установка Python-библиотек не нужны.

На macOS Graphviz можно установить командой `brew install graphviz`.
На Debian и Ubuntu используется `sudo apt install graphviz`.
На Windows установите Graphviz с официального сайта и используйте
`py -3 -m src.main` вместо `./run.sh`.

```sh
./run.sh --help
./run.sh --package quote --version 1.0.40
python3 -m unittest discover -s tests -v
```

| Параметр | Назначение |
| --- | --- |
| `--package` | Имя начального пакета. В тестовом режиме используется буква A–Z. |
| `--version` | Точная версия Cargo в формате SemVer. Обязательна в сетевом режиме. |
| `--repository` | HTTP(S)-адрес sparse-индекса либо путь к JSON. Адрес по умолчанию — `https://index.crates.io/`. |
| `--test` | Читать тестовый репозиторий из JSON. |
| `--filter` | Исключать зависимости, имя которых содержит указанную подстроку. Регистр игнорируется. |
| `--output-dir` | Каталог для файлов `.dot` и `.svg`. По умолчанию `out/`. |
| `--no-open` | Записать файлы без открытия браузера. |

В сетевом режиме нужны доступ к индексу и опубликованная версия пакета.
Некорректные опции возвращают код 2. Ошибки чтения и отрисовки вроде
недоступного индекса, отсутствующей версии или команды `dot` возвращают
код 1 и печатают причину.

## Как строится граф

Cargo-источник читает JSON Lines напрямую по HTTP. Например, файл с
релизами `quote` находится по пути `qu/ot/quote`. Программа находит точную
версию корня, извлекает поля зависимостей и для каждой связи независимо
выбирает наибольшую подходящую неотозванную версию SemVer. Узлы Cargo
помечаются как `имя@версия`. Учитываются обычные, сборочные,
опциональные и платформенные зависимости из указанного индекса.
Зависимости разработки пропускаются. Авторизация приватных индексов
и переход между несколькими индексами не поддерживаются.

Рекурсивный DFS сначала помечает текущий узел, затем перебирает его
соседей. Рёбра циклов сохраняются, а ранее посещённые узлы повторно
не обходятся. Фильтр действует на имя без версии. Начальная вершина
сохраняется, а отфильтрованные зависимости не обходятся.

[Формат индекса Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html) ·
[Диапазоны версий Cargo](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html) ·
[Команда Graphviz](https://graphviz.org/doc/info/command.html)

## Локальный тестовый репозиторий

В `tests/graph.json` ключи — пакеты, значения — списки их прямых
зависимостей. Каждый пакет, упомянутый в списке, должен иметь свою запись.
Пустой список означает отсутствие зависимостей.

```sh
./run.sh --test --repository tests/graph.json --package A
./run.sh --test --repository tests/graph.json --package A --filter C
./run.sh --test --repository tests/graph.json --package F
```

Первый запуск показывает цикл B → D → B и общую для B и C зависимость D.
Фильтр C оставляет A, B и D. Для F получается одна вершина без рёбер.

## Примеры визуализации Cargo

```sh
./run.sh --package itoa --version 1.0.18
./run.sh --package quote --version 1.0.40
./run.sh --package serde --version 1.0.228
```

Для каждого пакета команда создаёт DOT и SVG в `out/`. Например, для
`quote` файлы называются `quote@1.0.40.dot` и `quote@1.0.40.svg`.

## Сравнение с `cargo tree`

Графы программы получены из индекса crates.io. Для сравнения использованы
опубликованные результаты `cargo tree` с теми же версиями корневых пакетов.

| Пакет | Граф программы | Опубликованный результат Cargo |
| --- | --- | --- |
| `itoa@1.0.18` | Опциональное ребро к `no-panic`. | В дереве mousehop `itoa` — лист. |
| `quote@1.0.40` | `quote → proc-macro2 → unicode-ident`. | Та же цепочка в Cargo #15490. |
| `serde@1.0.228` | Рёбра к `serde_core` и `serde_derive`. | В Cargo #16990 есть оба ребра с feature `derive`. |

В примере с `quote` Cargo показывает `proc-macro2@1.0.95` и
`unicode-ident@1.0.18`. Программа выбирает наибольшие подходящие версии
из текущего индекса. В примере с `serde` в выводе Cargo `serde_core`
показан листом, а программа включает его платформенное объявление
зависимости от `serde_derive`.

Граф программы отражает объявления индекса, включая опциональные и
платформенные связи. `cargo tree` учитывает активные features, целевую
платформу и разрешение версий всего проекта, в том числе `Cargo.lock`.
Поэтому в графе программы могут появляться дополнительные узлы и другие
версии. Одинаковая стрелка в обеих визуализациях направлена от пакета к
его зависимости.

Чтобы повторить сравнение для отдельных пакетов, добавьте нужную точную
версию как зависимость в тестовый `Cargo.toml` вне проекта и выполните
`cargo tree -e normal,build`. Для `serde` включите feature `derive`.

[Дерево mousehop](https://docs.rs/mousehop/latest/mousehop/config/build/constant.CARGO_TREE.html) ·
[Cargo #15490](https://github.com/rust-lang/cargo/issues/15490) ·
[Cargo #16990](https://github.com/rust-lang/cargo/issues/16990) ·
[Справка cargo tree](https://doc.rust-lang.org/cargo/commands/cargo-tree.html)

## Этапы практики

| Этап | Результат |
| --- | --- |
| 1 | Разбор и проверка пяти параметров командной строки. |
| 2 | Вывод прямых зависимостей точной версии из индекса Cargo. |
| 3 | Рекурсивный DFS, фильтр, циклы и локальный JSON. |
| 4 | Обратные зависимости через DFS по развёрнутым рёбрам. |
| 5 | DOT, отрисовка SVG, показ изображения и сравнение с Cargo. |

Чтобы проверить этап 4, переключитесь на его коммит. В тестовом
репозитории для D ожидаются B, A, C, G. С фильтром C остаются B и A.
Для G обратных зависимостей нет.

```sh
git switch --detach main~1
./run.sh --test --repository tests/graph.json --package D --reverse
./run.sh --test --repository tests/graph.json --package D --reverse --filter C
./run.sh --test --repository tests/graph.json --package G --reverse
git switch main
```
